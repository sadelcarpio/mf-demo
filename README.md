# MF → Two-tower: watching users and items meet in embedding space

A Streamlit demo for the *Matrix Factorization* slides. It trains five recommenders on a tiny
videogame dataset and animates the user and item vectors (projected to 2-D) as they come together
during training.

| Page | Model | User vector | Item vector | Loss |
|---|---|---|---|---|
| 1 | MF (regression) | row of U | row of V | MSE on 1–5★ |
| 2 | Logistic MF | row of U | row of V | BCE on rating > threshold |
| 3 | Softmax over all items | encoder(user feats + history) | row of W (pre-softmax) | 1/n-target CE, temperature τ |
| 4 | Two-tower | user tower (L2-norm) | item tower (L2-norm) | in-batch softmax, B = 4, τ, logQ |
| 5 | Factorization machine | Σ v over user features | Σ v over item features | MSE or BCE |

## Run

```bash
uv sync
uv run streamlit run app.py
```

## Data (`data/`, ~8 KB)

Synthetic snapshot with no timestamps, generated by `uv run python data/generate_data.py` (seeded):

- `games.csv`: 20 games with category, tags and play mode
- `users.csv`: 60 users with platform, age group and self-reported favorite category
- `ratings.csv`: 539 ratings, 1–5★ (~45% of the matrix)

Cold start: users 56–59 have features but no ratings, and *Silent Hill f* is a new release with no
ratings. MF can't place them; the feature-based models can.

In the plots, each user is colored by the game category they rate highest on average.

## Code

- `mfdemo/data.py`: loading, feature encoding, train/test split
- `mfdemo/models.py`: the five PyTorch trainers. Each records 40 embedding snapshots.
- `mfdemo/viz.py`: PCA fit on the final epoch and applied to all snapshots (fixed axes), warm-started t-SNE per snapshot, plotly animation
- `app.py`: Streamlit UI
- `scripts/hp_search.py`: grid search that picked each model's defaults. It scores how cleanly users
  and games cluster by category in the default 2-D view, keeping only configs whose recall@5 is close
  to the model's best.
